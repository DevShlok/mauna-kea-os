# candidates

**Table:** `candidates` | **PK:** `id varchar(50)` (format: `CAND-<uuid>`)

## Purpose
Master person record for every executive candidate in the system. A candidate exists independently of any mandate or submission — they are the central entity that everything else links to.

## Notable Columns
- `id` — prefixed UUID (`CAND-<uuid>`), generated by `src/lib/ids.ts`
- `slug` — URL-safe unique slug used in portal routing (`/[slug]/`)
- `score` / `assessDate` — overwritten by rubric assessment engine (Phase 2); `score` = 0–100 total
- `expTags` (JSON string[]) — experience tags used for job matching
- `dreamRoles` / `dreamCos` (JSON string[]) — career aspirations, drives Dream 10 feature
- `auditLog` (JSON) — field-level change log: `{ [field]: { updatedBy, updatedAt } }` — see [[Decisions/field-level-audit-log]]
- `metadata` (JSON) — unstructured extension bag
- `profileCompletedAt` — null until onboarding is done; gates the candidate portal home vs onboarding shell
- `isDeleted` / `deletedAt` / `deletedBy` — soft delete; all queries must filter `isDeleted = false`
- `certifications`, `priorExperiences`, `pastCompanies` — JSON arrays, populated by CV parser
- `onboardingSource` — `'cv' | 'linkedin' | 'manual' | 'conversational'`
